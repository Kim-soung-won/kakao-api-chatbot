# 오픈빌더 시스템 블록 (웰컴·폴백·탈출)

> 카카오 i 오픈빌더 챗봇의 기본 3블록 개념과, 이 프로젝트 서버(`apps/server`)가
> 이를 어떻게 코드 구조로 반영했는지. 짝 문서: [chatbot.md](./chatbot.md).
> 출처: [챗봇 관리자센터 — 블록](https://i.kakao.com/docs/key-concepts-block).

## 블록이란

**블록(Block)** = 하나의 응답 단위. 사용자 발화가 블록의 발화 패턴과 매칭되면
그 블록의 응답을 낸다. 아래 3개는 오픈빌더가 기본 제공하는 **시스템 블록**이다.

## 1) 웰컴 블록 (Welcome)

- **언제:** 사용자가 봇을 **처음 접할 때 딱 1회**(채팅방 재진입마다 아님).
- **용도:** 첫 인사·온보딩 소개.
- **주의:** 매 대화마다 나오지 않는다. 재사용 인사는 별도 블록으로.

> ⚠️ **실측 이슈 — 웰컴 블록은 스킬 자동발송이 안 된다 (이 프로젝트에서 챗봇 웰컴 제거함).**
> 진입 웰컴은 **사용자 발화가 없어** 카카오가 스킬을 호출하지 않는다(스킬데이터 웰컴
> 블록은 진입 시 아무것도 안 뜨고 서버 로그도 안 찍힘). 정적 카드로 넣어도 실제 채널
> 진입에서 자동발송이 불안정했다(사업자 미인증 채널 등 조건 영향 추정).
> **결론: 진입 인사는 챗봇 웰컴 블록이 아니라 "채널 친구추가 메시지"(채널 관리자센터,
> 채널 레이어)로 처리한다.** 그래서 서버의 `welcome` 블록은 제거했고, 그 이후 대화만
> 챗봇 스킬(온보딩·폴백)이 담당한다.

## 2) 폴백 블록 (Fallback)

- **언제:** 발화가 **어떤 블록과도 매칭되지 않을 때**(봇이 못 알아들음).
- **용도:** 기본 응답. 이 프로젝트에서는 자유 질문을 **에이전트(A2A)**가 처리하므로, 서버 폴백은
  발화가 비었을 때 정도의 최종 안전망으로만 남는다(자유 질문은 `agent` 블록이 잡는다).

## 3) 탈출 블록 (Exit)

- **언제:** 봇이 **되묻는(파라미터 물어보는) 중**에 사용자가 그 흐름을 **초기화·이탈**하려 할 때.
- **용도:** "처음으로"·"취소"·"그만" 같은 탈출 명령어(오픈빌더 개념).
- ⚠️ 이 프로젝트 서버에는 **탈출 블록이 없다.** 에이전트 대화 "모드"(진입/종료)를 제거했기
  때문 — 온보딩 외 모든 발화가 항상 에이전트로 가므로 갇힐 모드 자체가 없다.

## 한눈에

| 블록 | 트리거 | 표준 용도 |
| --- | --- | --- |
| 웰컴 | 첫 진입(1회) | 인사·온보딩 (→ 채널 친구추가 메시지로 대체) |
| 폴백 | 발화 미매칭 | 기본 응답 (자유 질문은 에이전트가 처리) |
| 탈출 | 되묻기 중 이탈/초기화 | 흐름 리셋 (이 서버에선 미사용) |

## 이 프로젝트 서버의 대응 구조

서버는 오픈빌더 블록 개념을 **디스패처 + 블록 핸들러**로 옮겼다.
`POST /skill` → `parseSkillContext` → 매칭되는 블록이 `respond`(또는 콜백), 없으면 폴백.

```
apps/server/src/
  skill/
    types.ts              SkillContext, SkillBlock(계약)
    index.ts              parseSkillContext · handleSkill(디스패처)
    shared.ts             공통 quickReplies · wrap
    render-agent.ts       에이전트 답변 → SkillResponse 변환(임시 어댑터)
    blocks/
      index.ts            blocks[] (매칭 순서) + fallback
      onboarding.ts       온보딩 카드 흐름(지역→가구→관심). 완료 시 프로필을 에이전트로 전달(콜백)
      agent.ts            캐치올 — 온보딩 외 모든 발화를 A2A 에이전트로 전달(콜백)
      fallback.ts         최종 안전망(주로 빈 발화)
  a2a/                    A2A 클라이언트·설정·목업(client·config·mock)
  builders/outputs.ts     출력 컴포넌트 프리미티브 빌더
```

> **제거된 블록:** `welcome`(→ 채널 친구추가 메시지), `connect`/`exit`/`agent-chat`(에이전트 대화
> 모드 개념 폐기), `rag-search`(이력을 에이전트가 관리 → 별도 트리거 불필요), `welfare`/`help`
> (정적 카드 대신 에이전트가 응답).

- **매칭 순서**(`blocks/index.ts`): `onboarding → agent`, 마지막 안전망이 `fallback`.
  "맞춤복지"·온보딩 누적 발화만 `onboarding`이 잡고, 나머지 모든 발화는 `agent`로 간다.
- **콜백 처리**: `agent`(항상)와 `onboarding`(완료 단계만)은 5초를 넘길 수 있어 카카오
  콜백(useCallback)으로 최종 응답을 보낸다 → [a2a-callback.md](./a2a-callback.md).

## 오픈빌더 실제 연결 가이드

1. **온보딩 진입**(예: "맞춤복지")은 일반 블록에 발화 등록 + 스킬 연결.
2. **모든 자유 질문**은 **폴백 블록에 스킬(`/skill`) 연결** → 아무 발화나 우리 서버 → `agent` → A2A.
3. **콜백 활성화**: 챗봇 관리자센터에서 AI 챗봇 전환 + 스킬 콜백 켜기(그래야 `callbackUrl` 수신).
4. **진입 인사**는 챗봇 웰컴 블록이 아니라 **채널 관리자센터의 "친구 추가 메시지"**(채널 레이어)로
   등록한다. 그 메시지의 버튼(예: "맞춤 복지 안내 시작하기" → `맞춤복지`)이 챗봇 온보딩으로 이어지게.

> 서버는 어느 블록이 호출하든 `/skill` 한 엔드포인트로 받고, 발화로 내부 블록을
> 디스패치한다. 오픈빌더 블록과 서버 블록이 1:1일 필요는 없다.
