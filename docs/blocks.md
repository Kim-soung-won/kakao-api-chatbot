# 오픈빌더 시스템 블록 (웰컴·폴백·탈출)

> 카카오 i 오픈빌더 챗봇의 기본 3블록 개념과, 이 프로젝트 서버(`apps/server`)가
> 이를 어떻게 코드 구조로 반영했는지. 짝 문서: [chatbot.md](./chatbot.md).
> 출처: [챗봇 관리자센터 — 블록](https://i.kakao.com/docs/key-concepts-block).

## 블록이란

**블록(Block)** = 하나의 응답 단위. 사용자 발화가 블록의 발화 패턴과 매칭되면
그 블록의 응답을 낸다. 아래 3개는 오픈빌더가 기본 제공하는 **시스템 블록**이다.

## 1) 웰컴 블록 (Welcome)

- **언제:** 사용자가 봇을 **처음 접할 때 딱 1회**(채팅방 재진입마다 아님).
- **용도:** 첫 인사·온보딩 소개.
- **주의:** 매 대화마다 나오지 않는다. 재사용 인사는 별도 블록으로.

## 2) 폴백 블록 (Fallback)

- **언제:** 발화가 **어떤 블록과도 매칭되지 않을 때**(봇이 못 알아들음).
- **용도:** 기본 응답. **⭐ RAG를 붙이는 표준 위치** — 정형 발화로 못 받는 자유
  질문을 폴백 블록에 스킬로 연결하면 전부 우리 서버 → RAG로 흐른다.

## 3) 탈출 블록 (Exit)

- **언제:** 봇이 **되묻는(파라미터 물어보는) 중**에 사용자가 그 흐름을 **초기화·이탈**하려 할 때.
- **용도:** "처음으로"·"취소"·"그만" 같은 **탈출 명령어**를 정의하는 비상구.
- 다단계 시나리오에 갇히지 않게 한다.

## 한눈에

| 블록 | 트리거 | 표준 용도 |
| --- | --- | --- |
| 웰컴 | 첫 진입(1회) | 인사·온보딩 |
| 폴백 | 발화 미매칭 | 기본 응답 · **RAG 연결** |
| 탈출 | 되묻기 중 이탈/초기화 | 흐름 리셋 |

## 이 프로젝트 서버의 대응 구조

서버는 오픈빌더 블록 개념을 **디스패처 + 블록 핸들러**로 옮겼다.
`POST /skill` → `parseSkillContext` → 매칭되는 블록이 `respond`, 없으면 폴백.

```
apps/server/src/
  skill/
    types.ts              SkillContext, SkillBlock(계약)
    index.ts              parseSkillContext · handleSkill(디스패처)
    shared.ts             공통 quickReplies · wrap
    blocks/
      index.ts            blocks[] (매칭 순서) + fallback
      welcome.ts          웰컴 블록  ↔ 오픈빌더 웰컴
      onboarding.ts       시나리오 블록(지역→가구유형→관심분야)
      welfare.ts          복지 안내(캐러셀). 온보딩 결과로 재사용
      demos.ts            개발용 데모(카드·리스트·이미지·캐러셀·위반)
      exit.ts             탈출 블록  ↔ 오픈빌더 탈출(처음/취소/그만 → 리셋)
      fallback.ts         폴백 블록  ↔ 오픈빌더 폴백 (RAG 연결 지점)
  builders/outputs.ts     출력 컴포넌트 프리미티브 빌더
```

- **매칭 순서**(`blocks/index.ts`): `exit → onboarding → welcome → welfare → demos`,
  마지막 안전망이 `fallback`. 순서가 중요하다(예: "맞춤복지"는 onboarding이
  welfare보다 먼저 잡아야 함).
- **호출마다/케이스마다 분리**: 엔드포인트(`routes/`)·블록(`skill/blocks/`)·
  프리미티브(`builders/`)가 파일과 함수로 나뉜다.

## 오픈빌더 실제 연결 가이드

1. **정형 시나리오**(예: "복지", "맞춤복지")는 **일반 블록에 발화 등록** + 스킬 연결.
2. **자유 질문**은 **폴백 블록에 스킬(`/skill`) 연결** → 아무 발화나 우리 서버로.
3. **탈출**: 탈출 블록에 "처음으로"·"취소" 등록 → 서버 `exit` 블록이 리셋 응답.
4. 웰컴 블록에는 환영/온보딩 시작(우리 `welcome` 블록 내용)을 배치.

> 서버는 어느 블록이 호출하든 `/skill` 한 엔드포인트로 받고, 발화로 내부 블록을
> 디스패치한다. 오픈빌더 블록과 서버 블록이 1:1일 필요는 없다.
