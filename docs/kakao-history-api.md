# 카카오 대화 이력 조회 가능성 — 공식 API 조사

> "챗봇 대화 이력을 카카오에서 직접 조회하는 API가 있나?"에 대한 조사 결론 메모.
> 결론: **없다.** (과거엔 그래서 서버가 앱 레벨로 이력을 저장했으나, 현재는 **모든 질의가
> 에이전트를 거치며 이력을 에이전트가 관리**한다 → [rag-history.md](./rag-history.md).)
> 조사일: 2026-09. 짝 문서: [chatbot.md](./chatbot.md) · [blocks.md](./blocks.md).

## 한 줄 결론

카카오는 **오픈빌더 챗봇의 대화 이력을 조회하는 공개 API를 제공하지 않는다.** 스킬 서버가 받는
유일한 데이터는 매 요청의 `POST /skill`(=이번 발화)뿐이고, 과거 대화를 가져올 창구가 없다.
→ **앱 레벨 저장(현재: botUserKey별 파일 저장소)이 유일한 방법.**

## 후보별 조사 결과

| 후보 | 챗봇 대화 이력 조회? | 비고 |
| --- | --- | --- |
| 오픈빌더 스킬 서버(`/skill`) | ✗ | 매 요청 = 이번 발화만. 과거 턴 없음 |
| 대화 이력 조회 REST API | ✗ (미존재) | 카카오 공식 답변: 공개 API 없음, "챗봇관리자센터 문의" |
| 카카오 output context 왕복 | ✗ (실측 미동작) | 실카톡 진단상 `contexts` 매번 빈 배열 → [rag-history.md](./rag-history.md) |
| 상담톡 API/웹훅 | △ (상담원 채팅만) | **별개 제품**·계약 필요, **챗봇 대화는 제외** |
| 카카오톡 채널 웹훅 | ✗ | 친구추가/차단 이벤트만, 메시지 아님 |
| 메시지 API(알림톡·친구톡·메시지 보내기) | ✗ | **전송 전용**, 읽기 불가 |
| 카카오 로그인 | ✗ | 프로필만, 채팅 접근 불가 |

## 근거 요약

1. **오픈빌더 챗봇 — 조회 API 없음.** 금융권 담당자가 "사용자 발화·대화 내용·로그 저장/조회 가능
   여부"를 7개 항목으로 공식 문의했으나, 카카오 답변은 "챗봇관리자센터에 문의하라"로 종결 —
   개발자용 조회 API가 존재하지 않는다.
2. **상담톡은 별개 트랙.** 메시지 수·발신 내역을 볼 수 있는 건 **상담톡(사람 상담원 1:1 채팅)**
   뿐이며, 문서상 "**챗봇 수·발신 내용은 상담톡으로 조회할 수 없다**"고 명시. 별도 신청·유료·심사 대상.
3. **채널 웹훅은 메시지가 아님.** 사용자가 채널을 추가/차단했을 때의 이벤트 알림 용도.
4. **메시지 API는 전송 전용.** 알림톡·친구톡·메시지 보내기는 push만, 대화 읽기 기능 없음.

## 시사점 (설계 결정)

- 챗봇 대화 맥락은 **카카오가 보관·제공하지 않으므로 앱이 직접 저장**해야 한다. 이는 이 프로젝트의
  파일 저장소 결정(C4 designIntent d1·d10, [rag-history.md](./rag-history.md))을 뒷받침한다.
- 저장 키는 요청의 `userRequest.user.id`(botUserKey). 진단상 64자 해시로 안정적.
- 향후 **상담원 연결**이 중요해지면 상담톡을 붙여 상담원 채팅 이력을 웹훅으로 수신·저장할 수는
  있으나, 이는 챗봇 대화와 별도 트랙(사람 상담)이고 비용·심사가 따른다.
