# 카카오톡 채널 챗봇 개념 정리

> 이 프로젝트(sprint-kakao)의 **핵심** — 사용자가 채널에 말을 걸면 자동 응답하는 챗봇.
> 코드 계약은 `packages/contract/src/response.ts`(응답)·`request.ts`(요청, 가설),
> 서버는 `apps/server` `POST /skill`, 렌더 테스트는 `apps/playground` 좌측 채팅.
> 짝 문서: [친구톡](./friendtalk.md). 도메인 스킬: `kakao-skill-response_domain` / `_api`.
> 출처: 카카오 비즈니스 챗봇 가이드, 오픈빌더 스킬 개발 가이드.

## 한 줄 정의

**카카오톡 채널 챗봇** = 사용자가 채널 채팅방에 **말을 걸면(발화)**, 봇이 **자동으로
응답**하는 기능. **카카오 i 오픈빌더**로 만들고, 복잡한 응답은 **스킬 서버**에 위임한다.

## 명칭 체계 (헷갈리기 쉬움)

- **스마트채팅 (Smart Chatting)** — 채널 채팅 자동화의 **상위 개념**. 채널 관리자센터
  `설정 > 스마트채팅`에서 켠다. 두 모드:
  - **챗봇** — 봇이 자동 응답 (이 문서)
  - **상담톡** — 상담원이 실시간 채팅 (사람)
- **카카오 i 오픈빌더** — 챗봇을 만드는 저작 도구(시나리오·블록·스킬).

## 친구톡과 정반대 (가장 중요한 구분)

| | **챗봇** (이 문서) | 친구톡 |
|---|---|---|
| 방향 | **인바운드** 사용자→채널 | 아웃바운드 채널→사용자 |
| 계기 | 사용자가 **말을 검**(발화) | 채널이 **먼저**(push) |
| 성격 | 발화에 **응답**(pull) | 정보·광고 발송 |
| 제품 | 오픈빌더 챗봇 | 비즈메시지 |
| 계약 | `SkillResponse` | `FriendTalkMessage` |
| 온보딩 | 채널 + 오픈빌더 봇 | 발신프로필(sender_key) |

## 오픈빌더 구성 요소

- **시나리오(Scenario)**: 대화 주제 묶음.
- **블록(Block)**: 하나의 응답 단위. 사용자 발화가 블록에 매칭되면 그 응답을 낸다.
- **발화(Utterance) / 엔티티(Entity)**: 블록을 트리거하는 사용자 표현과 그 안의 개체값.
- **폴백 블록(Fallback)**: 어떤 블록에도 안 맞을 때의 기본 응답.
- **스킬(Skill)**: 블록의 응답을 **외부 서버(우리 스킬 서버)** 가 동적으로 생성하도록
  위임하는 연동. RAG 답변을 붙이는 지점이 바로 여기.

## 동작 흐름 (요청 → 응답 왕복)

```
사용자 발화
  → 오픈빌더가 블록 매칭
  → (스킬 블록이면) 우리 스킬 서버로 POST 요청  ── 인바운드 웹훅 ──
      body: 발화·user.id·contexts·action.params  (요청 계약 = 가설, /echo로 확정)
  → 서버가 SkillResponse(JSON) 반환
      outputs: simpleText·basicCard·listCard·itemCard·carousel + quickReplies
  → 카카오가 채팅창에 카드/버튼으로 렌더링
```

- 요청 포맷은 카카오 공개 문서에 없어 `request.ts`를 **가설(HYPOTHESIS)** 로 두고
  `POST /echo`로 실측 확정한다(user.id 고정성·contexts 왕복·params 수명).
- 응답은 렌더링 불변조건(outputs≤3, 캐러셀 비율 통일 등)을 지켜야 렌더 실패가 없다.

## 운영 제약

- **응답 타임아웃**: 동기 응답은 초 단위 제한. RAG처럼 오래 걸리면 **콜백(useCallback)**
  패턴으로 비동기 처리.
- **인증**: 별도 API 키가 아니라 **오픈빌더에 등록된 스킬 URL**로 신뢰(HTTPS 필수).
- 로컬 개발은 서버가 localhost라 카카오가 접근 못 함 → **터널/공개 배포**로 노출해야
  실제 왕복 가능(인바운드이기 때문). 아웃바운드 호출은 터널 불필요.

## 이 프로젝트에서의 위치 (이미 구현 중)

- 서버: `apps/server` `POST /skill`(발화→mock SkillResponse), `POST /echo`(요청 캡처)
- 계약: `packages/contract` `response.ts`(응답)·`request.ts`(요청, 가설)
- 렌더 테스트: `apps/playground` 좌측 채팅 시뮬레이터 + 제약 검증
- 아키텍처: `sprint-kakao-c4-model.json` — `sys-kakao-platform → cont-server` 인바운드
  웹훅 엣지, 저장소/요청계약 결정과 미결(/echo 실측)
- 다음: RAG 백엔드(Python) → SkillResponse 변환을 스킬 블록에 연결

## 챗봇 vs 상담톡 (같은 스마트채팅 안에서)

- **챗봇**: 봇 자동 응답(오픈빌더). 이 프로젝트의 대상.
- **상담톡**: 상담원 실시간 채팅. 봇이 못 푸는 질의를 넘기는 **폴백 경로**로,
  스킬 응답의 `operator` 버튼 액션으로 상담원 연결을 유도할 수 있다.
